### 1-2. 트랙1 규칙 — 누수 한 줄 요약

> 쓸 수 있는 변수의 기준은 "도축 전/후"가 아니라 **"test 13개 컬럼으로 계산 가능한가"** 다.
> WEIGHT·AGE·daily_gain은 가능(트랙1 OK), 육질 8개·WGRADE·COST_AMT는 불가(제출 모델 금지).

"참고-사후" 모델(육질 포함)은 **제출 불가**지만 "측정값이 있으면 얼마나 맞출 수 있는가"의 상한선을 보여주는 **보고서용 비교 분석**으로만 1회 돌린다.

### 1-3. 데이터가 3개다 — train / holdout / 진짜 test (혼동 주의)

가장 많이 헷갈리는 부분이다. 우리가 다루는 데이터는 **세 종류**다.

| | 무엇 | 정답(LAST_GRADE) | 행 수 | 역할 |
| --- | --- | --- | --- | --- |
| **train (정답 보유 전체)** | step11_features.csv | **있음** | 2,408,699 | 학습·검증의 재료 |
| ↳ **dev** | train의 80% | 있음 | 약 192만 | 5-fold CV로 학습·튜닝 |
| ↳ **holdout** | train의 20% | 있음 | 약 48만 | "처음 보는 데이터" 흉내 — 자체 최종 점검 1회 |
| **진짜 test (제출용)** | `data/test/test_hanwoo.csv` | **없음(전부 빈칸)** | 452,497 | 대회 제출 — 우리가 예측해서 채워 넣을 대상 |

핵심 구분:
- **holdout**은 train을 쪼갠 것이라 정답이 있어서 "내 모델이 몇 점인지" 우리가 직접 채점할 수 있다. 그래서 튜닝이 끝난 뒤 **단 한 번** 보는 자체 시험지다.
- **진짜 test**는 정답이 없다(대회 주최측만 안다). 우리는 예측값을 만들어 제출하고, 점수는 리더보드로만 안다. 그래서 holdout이 "test의 대역(代役)" 역할을 한다 — holdout 점수가 곧 제출 점수의 예상치다.

> **즉 "train/test 나눴냐?"에 대한 답**: ① 학습 검증용으로 train 안에서 dev/holdout을 농장 단위로 나눴고(이미 완료), ② 진짜 제출용 test는 별도 파일로 존재하며 **본 강의안 12장에서 동일 파이프라인으로 예측해 제출 파일을 만든다.** test에는 기상 파생이 없으므로(원본 13컬럼뿐) train과 똑같은 병합·전처리·파생을 그대로 적용하는 것이 12장의 핵심이다.

## 2. 이론 — 꼭 알고 시작할 것들

### 2-1. 정확도(Accuracy)의 함정

```
정확도 = 맞춘 수 / 전체 수
```

우리 데이터는 1++B 혼자 13.3%다. 16개 등급 중 상위 몇 개만 찍어도 정확도는 그럴듯하게 나온다. **불균형 58배에서 정확도는 거의 무의미**하다.

### 2-2. 정밀도·재현율·F1 (공식)

어떤 한 등급(예: 1++A)에 대해:

```
정밀도(Precision) = TP / (TP + FP)   — 모델이 "1++A"라고 한 것 중 진짜 비율
재현율(Recall)    = TP / (TP + FN)   — 진짜 1++A 중 모델이 잡아낸 비율
F1 = 2 · (정밀도 × 재현율) / (정밀도 + 재현율)   — 둘의 조화평균
```

조화평균이라서 **둘 중 하나라도 0에 가까우면 F1도 0에 가깝다** — 정밀도만 높고 재현율이 바닥인 "꼼수"를 막는다.

### 2-3. Macro-F1 (대회 평가지표)

```
Macro-F1 = (1/K) · Σₖ F1ₖ     (K = 16개 등급)
```

각 등급의 F1을 **표본 수와 무관하게 단순 평균**한다. 등외(5,540마리)의 F1과 1++B(319,588마리)의 F1이 **같은 가중치**다. → 소수 등급을 포기하는 모델은 Macro-F1이 크게 깎인다. 이것이 아래 모든 모델에 클래스 가중치를 넣는 이유다.

### 2-4. 클래스 가중치 (class_weight="balanced")의 공식

```
wₖ = N / (K · nₖ)     (N=전체 표본, K=클래스 수, nₖ=클래스 k의 표본 수)
```

등외처럼 드문 클래스의 오류에 더 큰 벌점을 줘서, 모델이 소수 클래스를 포기하지 않게 만든다. 예: 등외 w ≈ 2,408,699/(16×5,540) ≈ 27배 가중.

### 2-5. 농장 단위 분할 — 왜 일반 KFold면 안 되나

같은 농장의 소들은 사료·관리·유전이 비슷해서 서로 닮았다. 무작위로 나누면 **같은 농장의 소가 학습/검증 양쪽에 들어가**, 모델이 "농장 외우기"로 점수를 부풀린다(그룹 누수). 실제 test의 새 농장에서는 성능이 폭락한다.

→ **StratifiedGroupKFold**: 같은 농장(FARM_UNIQUE_NO)은 반드시 같은 fold에(Group), 등급 비율은 fold마다 유지(Stratified).

> 분할은 이미 만들어져 검증까지 끝났다(`split_assignment.csv`): 농장 누수 0건, 5개 fold 모두 16등급 포함, 홀드아웃 정확히 20%. **회귀팀과 같은 파일을 쓴다** — 두 트랙 결과를 비교 가능하게 만드는 장치다.

### 2-6. 그래디언트 부스팅 3형제 — 공통 원리와 차이

셋 다 **약한 트리를 순차적으로 쌓아 이전 모델의 오류(그래디언트)를 보정**하는 부스팅이다:

```
F₀(x) = 초기값
Fₘ(x) = Fₘ₋₁(x) + ν · hₘ(x)
   hₘ = 현재 모델의 손실 그래디언트(≈잔차)를 가장 잘 맞추는 트리
   ν  = learning_rate (한 걸음의 크기)
```

| | LightGBM | XGBoost | CatBoost |
| --- | --- | --- | --- |
| 트리 성장 | **leaf-wise** (손실 가장 큰 잎부터 분할 → 빠르고 깊게) | level-wise 기본 (층별 균등 분할 → 안정적) | **대칭 트리** (모든 층이 같은 분할 → 과적합에 강함) |
| 속도 | 가장 빠름 (히스토그램 기반) | 빠름 (`tree_method="hist"`) | 상대적으로 느림 |
| 강점 | 대용량·기본 성능 | 정밀한 정규화 (목적함수에 Ω(h)=γT+½λ‖w‖² 포함) | 순서형 부스팅으로 타깃 누수에 강함, 범주형 자동 처리 |
| NaN | 자동 처리 | 자동 처리 | 자동 처리 |
| 클래스 가중 | `class_weight="balanced"` | `sample_weight` 직접 전달 | `auto_class_weights="Balanced"` |

**로지스틱 회귀**는 비교 기준점(베이스라인)이다. 다항(소프트맥스) 형태:

```
P(y=k | x) = exp(βₖᵀx) / Σⱼ exp(βⱼᵀx)
```

선형 결정경계만 그릴 수 있고, 스케일에 민감해서 **표준화가 필수**이며, NaN을 못 받아 **중앙값 대치가 필수**다. "트리 모델이 이 단순한 모델보다 얼마나 나은가"를 재는 자(尺)다.

### 셀 3 (코드) — 데이터 로드 + 분할 병합

```python
# ==============================================================
# step11 로드 + 분할(split_assignment) 병합
# ==============================================================
df = pd.read_csv("../../data/processed/3_eda/step11_features.csv",
                 encoding="utf-8-sig", low_memory=False)
print(f"데이터: {df.shape}")   # (2408699, 92)

SPLIT_PATH = "../../data/processed/4_model/split_assignment.csv"

if os.path.exists(SPLIT_PATH):
    split = pd.read_csv(SPLIT_PATH, encoding="utf-8-sig")
    print("기존 분할 로드 (회귀팀과 공유) — 새로 만들지 말 것!")
else:
    # 최초 1회만 실행됨 — 농장 단위 + 등급 비율 유지 분할
    from sklearn.model_selection import StratifiedGroupKFold
    sgkf = StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=SEED)
    dev_idx, hold_idx = next(sgkf.split(df, df["LAST_GRADE"],
                                        groups=df["FARM_UNIQUE_NO"]))
    df["split"] = "dev"; df.loc[hold_idx, "split"] = "holdout"
    df["fold"] = -1
    dev_tmp = df[df["split"] == "dev"]
    sgkf2 = StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=SEED)
    for k, (_, va) in enumerate(sgkf2.split(dev_tmp, dev_tmp["LAST_GRADE"],
                                            groups=dev_tmp["FARM_UNIQUE_NO"])):
        df.loc[dev_tmp.index[va], "fold"] = k
    df[["CATTLE_NO","split","fold"]].to_csv(SPLIT_PATH, index=False,
                                            encoding="utf-8-sig")
    split = df[["CATTLE_NO","split","fold"]]
    print("분할 새로 생성 후 저장")

df = df.merge(split, on="CATTLE_NO", how="left") if "split" not in df.columns else df
print(df["split"].value_counts())
print("dev fold 분포:\n", df[df['split']=='dev']['fold'].value_counts().sort_index())

# 분할 자체 검증 — 농장이 두 영역에 걸치면 누수
farm_check = df.groupby("FARM_UNIQUE_NO")["split"].nunique()
assert (farm_check > 1).sum() == 0, "농장 누수 발견! 분할 파일 확인 필요"
print("농장 누수 검증 통과")
```

**무엇을 하는 코드인가**: ① step11(92변수) 로드 → ② 공유 분할 파일을 병합(없으면 생성 — 단 이미 만들어져 있으므로 로드만 됨) → ③ 농장 누수가 없는지 assert로 즉석 검증. 검증을 코드에 박아 두면 분할 파일이 잘못 바뀌었을 때 바로 멈춘다.

### 셀 6 (코드) — 개발/홀드아웃 분리 + 방어적 결측 처리 함수

```python
# ==============================================================
# dev/holdout 분리 + 결측 처리 유틸
# ==============================================================
dev  = df[df["split"] == "dev"].reset_index(drop=True)
hold = df[df["split"] == "holdout"].reset_index(drop=True)
print(f"개발: {len(dev):,} / 홀드아웃: {len(hold):,}")

def prepare_X(train_X, *other_Xs):
    """train 중앙값으로 결측 대치 (누수 방지: 중앙값은 train에서만 계산).
    ① inf→NaN ② train 중앙값 대치 ③ 그래도 NaN인(전부결측) 컬럼은 제거."""
    train_X = train_X.replace([np.inf, -np.inf], np.nan)
    med = train_X.median(numeric_only=True)
    out = [train_X.fillna(med)]
    for X_ in other_Xs:
        out.append(X_.replace([np.inf, -np.inf], np.nan).fillna(med))
    # 전부 결측이라 중앙값조차 없는 컬럼 방어 (실데이터 스모크에서 실제 발생)
    bad = out[0].columns[out[0].isnull().any()].tolist()
    if bad:
        print(f"  [방어] 전부 결측 컬럼 제거: {bad}")
        out = [o.drop(columns=bad) for o in out]
    return out if len(out) > 1 else out[0]

# fold 인덱스 리스트 (위치 기반)
fold_indices = [(np.where(dev["fold"] != k)[0], np.where(dev["fold"] == k)[0])
                for k in range(5)]
y_dev = dev["y"]

# ★ heat_high 임계값을 dev 분위 하나로 통일 (train·test 동일 기준선)
#   step11의 heat_high는 전체(2.4M) 분위로 만들어졌음 → dev 분위로 다시 계산해 일관성 확보
HEAT_Q75 = float(np.nanquantile(dev["ratio_고온"], 0.75))   # ← test에서도 이 값을 재사용
for part in (dev, hold):
    part["heat_high"] = (part["ratio_고온"] >= HEAT_Q75).astype(int)
X_t1 = dev[features_track1]                                  # heat_high 갱신 반영
print(f"heat_high 임계값(dev 75분위) = {HEAT_Q75:.4f}")
```

**중앙값을 train에서만 계산하는 이유**: 검증 fold의 중앙값을 쓰면 검증 정보가 학습에 새어 들어간다(전처리 누수). 트리 3종은 NaN을 자동 처리하므로 사실 대치가 불필요하지만, 로지스틱과의 **공정 비교**를 위해 같은 입력을 쓴다.

**heat_high를 다시 계산하는 이유**: 17회차에서 step11을 만들 때 heat_high 임계값을 전체 240만 행 기준으로 잡았다. 그런데 test에는 그 임계값이 없으니 dev에서 다시 구해야 하는데, 그러면 train(전체 분위)과 test(dev 분위)가 **서로 다른 기준선**을 쓰게 된다. 그래서 여기서 train(dev·hold)도 dev 분위로 다시 계산해 **train과 test가 똑같은 `HEAT_Q75`를 공유**하게 만든다. (80% 분위 vs 100% 분위라 값 차이는 작지만, 기준을 일치시키는 게 원칙.)

### 셀 7 (코드) — 공통 CV 러너

```python
# ==============================================================
# 공통 5-fold CV 러너 — 4개 모델을 같은 조건에서
# ==============================================================
def run_cv(name, make_model, X_all, y_all, fold_indices,
           n_folds=5, needs_scaling=False, use_sample_weight=False,
           fit_kwargs_fn=None):
    """make_model(): 새 모델 객체 반환. fit_kwargs_fn(X_va,y_va): fit 추가 인자."""
    results, oof = [], np.full(len(X_all), -1, dtype=int)
    last_model = None
    for fold_i, (tr_idx, va_idx) in enumerate(fold_indices[:n_folds]):
        X_tr, X_va = X_all.iloc[tr_idx], X_all.iloc[va_idx]
        y_tr, y_va = y_all.iloc[tr_idx], y_all.iloc[va_idx]
        X_tr, X_va = prepare_X(X_tr, X_va)

        if needs_scaling:
            sc = StandardScaler()
            X_tr = pd.DataFrame(sc.fit_transform(X_tr), columns=X_tr.columns)
            X_va = pd.DataFrame(sc.transform(X_va),  columns=X_va.columns)

        model = make_model()
        kwargs = fit_kwargs_fn(X_va, y_va) if fit_kwargs_fn else {}
        if use_sample_weight:   # XGBoost용 — 클래스 균형 가중치
            kwargs["sample_weight"] = compute_sample_weight("balanced", y_tr)
        model.fit(X_tr, y_tr, **kwargs)

        pred = np.asarray(model.predict(X_va)).ravel().astype(int)  # ★CatBoost (n,1) 대응
        oof[va_idx] = pred
        f1m = f1_score(y_va, pred, average="macro")
        acc = accuracy_score(y_va, pred)
        results.append({"fold": fold_i, "macro_f1": round(f1m,4), "acc": round(acc,4)})
        print(f"  [{name}] fold {fold_i}: Macro-F1={f1m:.4f}, Acc={acc:.4f}")
        last_model = model
    r = pd.DataFrame(results)
    print(f"  [{name}] 평균 Macro-F1 = {r['macro_f1'].mean():.4f} ± {r['macro_f1'].std():.4f}")
    return r, oof, last_model
```

`.ravel().astype(int)` 한 줄이 CatBoost의 2차원 predict를 흡수한다 — 4개 모델이 한 함수로 돈다.

### 셀 14 (코드) — Optuna 튜닝 (LightGBM)

```python
# ==============================================================
# Optuna — LightGBM 하이퍼파라미터 탐색 (fold 0으로 평가)
# ==============================================================
N_TRIALS = 20           # TODO: 시간에 따라 조정 (10~50). 1 trial ≈ 수 분

tr_idx, va_idx = fold_indices[0]

y_tr0, y_va0 = y_dev.iloc[tr_idx], y_dev.iloc[va_idx]

def objective(trial):
    params = dict(
        objective="multiclass", num_class=n_classes,
        learning_rate=trial.suggest_float("learning_rate", 0.02, 0.15, log=True),
        n_estimators=trial.suggest_int("n_estimators", 300, 1500, step=100),
        max_depth=trial.suggest_int("max_depth", 5, 12),
        num_leaves=trial.suggest_int("num_leaves", 31, 255),
        min_child_samples=trial.suggest_int("min_child_samples", 20, 200),
        subsample=trial.suggest_float("subsample", 0.6, 1.0),
        colsample_bytree=trial.suggest_float("colsample_bytree", 0.6, 1.0),
        reg_alpha=trial.suggest_float("reg_alpha", 1e-3, 10.0, log=True),
        reg_lambda=trial.suggest_float("reg_lambda", 1e-3, 10.0, log=True),
        class_weight="balanced", verbose=-1, n_jobs=-1, random_state=SEED)
    m = lgb.LGBMClassifier(**params)
    m.fit(X_tr0, y_tr0, eval_set=[(X_va0, y_va0)],
          callbacks=[lgb.early_stopping(30, verbose=False)])
    return f1_score(y_va0, np.asarray(m.predict(X_va0)).ravel(),
                    average="macro")

study = optuna.create_study(direction="maximize",
                            sampler=optuna.samplers.TPESampler(seed=SEED),
                            pruner=optuna.pruners.MedianPruner())
study.optimize(objective, n_trials=N_TRIALS, show_progress_bar=True)
print(f"\n최적 Macro-F1(fold0): {study.best_value:.4f}")
print(json.dumps(study.best_params, indent=2))
```

**탐색 공간 설명** — 각 파라미터가 무엇을 조절하나:
| 파라미터 | 늘리면 | 과적합 위험 |
| --- | --- | --- |
| `learning_rate` ↓ + `n_estimators` ↑ | 더 정밀한 학습 | ↓ (대신 느려짐) |
| `max_depth`, `num_leaves` ↑ | 더 복잡한 패턴 포착 | ↑ |
| `min_child_samples` ↑ | 잎이 더 일반적 | ↓ |
| `subsample`, `colsample_bytree` ↓ | 무작위성 증가 | ↓ |
| `reg_alpha`(L1), `reg_lambda`(L2) ↑ | 가중치 억제 | ↓ |

## 3.5 대회 test 예측 & 제출 파일 만들기 (★ 실제 제출의 핵심)

> **이 셀(21)이 만드는 건 "일단 도는" 베이스라인 제출(순수 argmax)이다.** 3.7(가중)·3.8(스태킹)의 개선은 그 뒤에 나오므로, **최종 제출은 맨 끝 3.9(셀 24)에서 재생성**한다. 위→아래로 실행하면 3.9가 마지막에 최선의 제출로 덮어쓴다.

지금까지는 정답이 있는 train 안에서만 놀았다. 이제 **정답이 없는 진짜 test 452,497마리의 등급을 예측해서 제출 파일을 만든다.** test는 원본 13컬럼뿐이라, **train에 했던 병합·전처리·파생을 토씨 하나 안 틀리게** 다시 적용해야 한다. 한 군데라도 다르면 모델이 엉뚱한 숫자를 받아 예측이 무너진다.

### 누수 방지 3대 원칙 (test 처리에서 반드시)

1. **빈도·통계는 train에서 배운 것을 test에 "적용"만** 한다 (test로 다시 학습 금지). 혈통 빈도 맵, 결측 대치 중앙값이 여기 해당.
2. **더미 컬럼은 train 목록에 맞춰 정렬**한다. test에만 있는 카테고리는 버리고, train에 있는데 test에 없으면 0으로 채운다 (모델 입력 컬럼 순서·개수가 정확히 같아야 함).
3. **기상 집계는 같은 날씨 테이블**(step4-3)로 train과 동일 방식. test 관측소 199곳은 전부 날씨 테이블에 있음을 확인했다.

### 셀 20 (코드) — test 피처 빌드 함수 (검증 완료)

```python
# ==============================================================
# test_hanwoo.csv → step11과 동일 구조의 피처로 변환
#   (실데이터로 병합·기상집계·파생·빈도·더미 전 구간 검증된 코드)
# ==============================================================
def build_features_for_test(test_path="../../data/test/test_hanwoo.csv"):
    test = pd.read_csv(test_path, low_memory=False)
    for c in ["ABATT_DATE", "BIRTH_YMD", "JUDGE_DATE"]:
        test[c] = pd.to_datetime(test[c], errors="coerce")

    # ── (1) 농장/개체 병합: death, area, lineage (train과 동일 규칙) ──
    death = pd.read_csv("../../data/raw/hanwoo_death.csv")
    test = test.merge(death.groupby("FARM_UNIQUE_NO").size()
                      .rename("death_count").reset_index(),
                      on="FARM_UNIQUE_NO", how="left")
    area = pd.read_csv("../../data/raw/hanwoo_area.csv")
    for c in ["C2023", "C2024", "C2025", "AREA"]:
        area[c] = area[c].replace(-99, np.nan)
    test = test.merge(area.groupby("FARM_UNIQUE_NO")[["C2023","C2024","C2025","AREA"]]
                      .sum().reset_index(), on="FARM_UNIQUE_NO", how="left")
    lin = pd.read_csv("../../data/raw/hanwoo_lineage_0612.csv", low_memory=False)  # 0612 교정본
    test = test.merge(lin, on="CATTLE_NO", how="left")

    # ── (2) 기상 생애 노출 집계 (step4-4 누적합 방식, 동일 날씨 테이블) ──
    w = pd.read_csv("../../data/processed/1_merge/step4-3_weather.csv",
                    usecols=["stn","date","THI_grade","rn_day","ws_davg","ta_min"],
                    low_memory=False)
    w["date"] = pd.to_datetime(w["date"])
    for g in ["양호","주의","경고","위험","폐사"]:
        w[f"d_{g}"] = (w["THI_grade"] == g).astype(int)
    sum_cols = ["d_양호","d_주의","d_경고","d_위험","d_폐사","rn_day","ws_davg","ta_min"]
    test = test.reset_index(drop=True)
    n = len(test)
    days_arr = np.full(n, np.nan); seg = np.full((n, len(sum_cols)), np.nan)
    for stn, ws in w.groupby("stn"):
        ws = ws.sort_values("date"); dates = ws["date"].values
        csum = np.vstack([np.zeros(len(sum_cols)), ws[sum_cols].cumsum().values])
        idx = np.where(test["stn"].values == stn)[0]
        if len(idx) == 0:
            continue
        lo = np.searchsorted(dates, test["BIRTH_YMD"].values[idx], side="left")
        hi = np.searchsorted(dates, test["ABATT_DATE"].values[idx], side="right")
        seg[idx] = csum[hi] - csum[lo]; days_arr[idx] = hi - lo
    test["days_total"] = days_arr
    for i, g in enumerate(["양호","주의","경고","위험","폐사"]):
        test[f"days_{g}"] = seg[:, i]
    with np.errstate(invalid="ignore", divide="ignore"):
        test["rn_day_mean"]  = seg[:, 5] / days_arr
        test["ws_davg_mean"] = seg[:, 6] / days_arr
        test["ta_min_mean"]  = seg[:, 7] / days_arr

    # ── (3) 기상 비율 (15회차) ──
    test["ratio_고온"]   = (test["days_주의"]+test["days_경고"]+test["days_위험"]) / test["days_total"]
    test["ratio_강더위"] = (test["days_경고"]+test["days_위험"]) / test["days_total"]
    test["ratio_위험"]   = test["days_위험"] / test["days_total"]

    # ── (4) 시간·효율·임계·농장·상호작용 파생 (16~17회차) ──
    test["abatt_year"]    = test["ABATT_DATE"].dt.year
    test["abatt_month"]   = test["ABATT_DATE"].dt.month
    test["abatt_quarter"] = test["ABATT_DATE"].dt.quarter
    test["birth_year"]    = test["BIRTH_YMD"].dt.year
    test["birth_month"]   = test["BIRTH_YMD"].dt.month
    def to_season(m):
        return ("봄" if m in [3,4,5] else "여름" if m in [6,7,8]
                else "가을" if m in [9,10,11] else "겨울")
    test["abatt_season"] = test["abatt_month"].map(to_season)
    test["birth_season"] = test["birth_month"].map(to_season)
    test["fattening_days"] = (test["ABATT_DATE"] - test["BIRTH_YMD"]).dt.days
    test["daily_gain"]     = test["WEIGHT"] / test["fattening_days"]
    test["Age_squared"]    = test["AGE"] ** 2
    test["age_optimal"]    = ((test["AGE"] >= 28) & (test["AGE"] <= 32)).astype(int)
    # heat_high: 셀 6에서 dev로 구한 HEAT_Q75를 그대로 사용 (train과 동일 기준선, test 재계산 금지)
    test["heat_high"] = (test["ratio_고온"] >= HEAT_Q75).astype(int)
    test["density"]    = (test["C2025"] / test["AREA"]).replace([np.inf,-np.inf], np.nan)
    test["death_rate"] = (test["death_count"] / test["C2025"]).replace([np.inf,-np.inf], np.nan)
    test["density_x_heat"] = test["density"] * test["ratio_고온"]

    # ── (5) 혈통 빈도 인코딩: TRAIN에서 배운 빈도를 매핑 (누수 방지) ──
    for col in ["KPN_NO","FATHER_CATTLE_NO","MOTHER_ANIMAL_NO"]:
        freq_map = (df[[col, f"{col}_freq"]].dropna()
                      .drop_duplicates().set_index(col)[f"{col}_freq"].to_dict())
        test[f"{col}_freq"] = test[col].map(freq_map)   # train에 없는 신규값 → NaN

    # ── (5b) EBV(외부 유전능력) 조인 + 조상 본인등급 (★ step11과 동일하게) ──
    #   EBV: KPN명호=KPN_NO 해시로 조인. 외부 계산값이라 누수 0. 결측은 셀21 중앙값 대치.
    g = pd.read_excel("../../data/raw/KPN 유전능력 자료.xlsx")
    g["KPN명호"] = g["KPN명호"].astype(str).str.strip()
    g = g[~g["KPN명호"].isin(["nan", ""])].drop_duplicates("KPN명호")
    emap = {"근내지방도 육종가":"ebv_marbling", "근내지방도 정확도":"ebv_marbling_acc",
            "도체중 육종가":"ebv_cwt", "등심단면적 육종가":"ebv_rea",
            "등지방두께 육종가":"ebv_backfat", "12개월체중 육종가":"ebv_wt12"}
    gg = g[["KPN명호"] + list(emap)].rename(columns={"KPN명호":"KPN_NO", **emap})
    for c in emap.values():
        gg[c] = pd.to_numeric(gg[c], errors="coerce")
    test["KPN_NO"] = test["KPN_NO"].astype(str).str.strip()
    test = test.merge(gg, on="KPN_NO", how="left")
    test["has_ebv"] = test["ebv_marbling"].notna().astype(int)

    #   조상 본인등급: TRAIN(df)에서 조회 + 날짜 게이트(조상 판정 < test 송아지 판정 → 미래정보 차단)
    rec = df.dropna(subset=["CATTLE_NO"]).drop_duplicates("CATTLE_NO").set_index("CATTLE_NO")
    rec_jd = pd.to_datetime(rec["JUDGE_DATE"], errors="coerce")
    rec_g  = pd.to_numeric(rec["grade_num"], errors="coerce")
    for idcol, nm in [("MOTHER_ANIMAL_NO","mother"), ("FATHER_CATTLE_NO","father")]:
        a_jd = test[idcol].map(rec_jd); a_g = test[idcol].map(rec_g)
        gated = np.where(a_jd.values < test["JUDGE_DATE"].values, a_g.values, np.nan)
        test[f"{nm}_own_grade"] = gated
        test[f"has_{nm}_grade"] = (~np.isnan(gated)).astype(int)

    # ── (5c) weight_vs_peer: 월령+성별 또래 평균체중 대비 (CV +0.0021, 타깃 미사용=누수0) ──
    peer_w = df.groupby(["AGE", "JUDGE_SEX"])["WEIGHT"].mean().rename("peer_w")  # train 기준
    test = test.merge(peer_w.reset_index(), on=["AGE", "JUDGE_SEX"], how="left")
    test["weight_vs_peer"] = test["WEIGHT"] / test["peer_w"]
    test = test.drop(columns=["peer_w"])

    # ── (6) 원-핫 더미: train 컬럼에 맞춰 정렬 ──
    test["sex"] = test["JUDGE_SEX"]   # get_dummies prefix 맞추기용
    dummies = pd.get_dummies(test[["sido","abatt_season","birth_season","sex"]],
                             prefix=["sido","abatt_season","birth_season","sex"]).astype(int)
    train_dummy_cols = [c for c in features_track1
                        if c.startswith(("sido_","abatt_season_","birth_season_","sex_"))]
    for col in train_dummy_cols:
        test[col] = dummies[col] if col in dummies.columns else 0   # 없으면 0
    return test

test_feat = build_features_for_test()
print(f"test 피처화 완료: {test_feat.shape}")

# 트랙1 피처가 빠짐없이 만들어졌는지 검증
missing_cols = [c for c in features_track1 if c not in test_feat.columns]
assert not missing_cols, f"누락 피처: {missing_cols}"
print(f"트랙1 {len(features_track1)}개 피처 전부 생성 확인")
```

## 3.6 우리가 만든 파생변수 — 목록·선택법·추가하는 법 (★ 베이스라인과 분리)

> 셀 1–21(베이스라인 코드)은 **그대로 둔다.** 이 파트는 "우리가 *추가로* 시도한 파생변수"만 한곳에 모은 **실험 기록 + 재사용 틀**이다. 나중에 새 파생변수를 떠올리면 **3.6.4 코드에 한 줄 추가**해 같은 방식으로 검증하면 된다. (이 파트의 채택분은 이미 step11과 test 빌드(셀 20)에 반영돼 있음.)

### 3.6.1 방법론 — "하나씩 넣어보기" vs "모델이 알아서 고르기"

질문: **하나씩 넣어보고 오르면 넣고 떨어지면 빼야 하나, 아니면 단계선택법처럼 모델이 알아서 유의미한 것만 남기나?** 두 길이 있다.

**(A) 하나씩 격리 검증 (= 수동 forward selection, 우리가 쓰는 법)** — 후보 변수를 하나 넣고 CV 점수를 본다 → 오르면 채택, 안 오르면 기각.

**(B) 모델이 알아서 (자동 선택)**
- 고전 **단계선택법(stepwise — AIC·p값으로 변수 넣고 빼기)**: **선형회귀·로지스틱 전용**이다. 트리(LightGBM)는 변수별 p값이 없어 stepwise를 안 쓴다.
- 트리용 자동선택은 **permutation importance / null importance / Boruta / RFE** 같은 래퍼 방법이 따로 있다.

**그럼 우리는 왜 (A) 하나씩 하나?** 사실 트리는 **쓸모없는 변수를 자동으로 무시**한다(그 변수로 split을 안 함). 그래서 "다 넣어도 대체로 무해"하다. 그런데도 하나씩 격리하는 이유는 둘:

1. **누수 탐지 (제일 중요).** 누수가 있는 변수는 **importance·SHAP에서 오히려 최상위로 보인다** → 모델·중요도로는 절대 못 거른다. 오직 **검증셋 점수가 떨어지는지**로만 잡힌다. (자손 target-encoding이 그 예: SHAP상으론 멀쩡한데 격리 CV에서 −0.02 → 안 돌렸으면 모르고 제출할 뻔했다.)
2. **노이즈 희석.** 효과 없는 변수를 같이 넣으면 컬럼 서브샘플링 등으로 **오히려 깎인다** (우리 실측: 결합 +0.0013 < weight_vs_peer 단독 +0.0021).

**→ 권장 절차**: ① 후보를 누수 없게 만든다 → ② 격리 CV로 **하나씩** (누수+효과 동시 확인) → ③ 오르면 채택/내리면 기각 → ④ 채택분만 모아 **결합 CV**로 희석 점검 → ⑤ 전체 5-fold로 최종 확정.

> **누수 판정 기준**: "test 13컬럼이냐"가 아니라 **"이 송아지 도축(판정) 시점보다 과거에 알 수 있었나"**(시간 기준). 타깃(등급)을 *직접 가공*한 변수(target-encoding)는 OOF·자기제외로 통제하고, *외부값*(EBV)이나 *다른 변수로만 만든 값*(weight_vs_peer)은 타깃을 안 써서 그냥 안전하다(OOF 불필요).

### 3.6.2 용어와 계산법 (한 번만 읽으면 됨)

**파생변수란?** 원래 데이터에 없던 새 열을, 기존 정보로 계산해 만든 것. 모델은 숫자만 먹으므로 "KPN 종모우 번호"(해시 문자열)처럼 글자로 된 건 그대로 못 쓰고 **숫자 열로 바꿔야** 한다. (등급은 셀 5에서 `grade_num`으로 숫자화: 등외=0 … 1++A=15)

**① 빈도(frequency) — `KPN_NO_freq`** *(원래 있던 것)* — "이 종모우가 데이터에 몇 번 나오나" = 자손 수. 종모우 번호별 행 개수(`value_counts`). 예: 종모우 A가 8만 마리 아빠면 그 새끼들은 전부 `KPN_NO_freq=80000`.

**② EBV(육종가) — `ebv_marbling`·`ebv_cwt` 등** *(우리가 계산 안 함, 외부 파일)* — 한우개량사업소가 공식 발표한 **"이 종모우의 새끼가 평균적으로 마블링·도체중이 얼마나 좋을지"의 유전 점수**(EBV=Estimated Breeding Value, 추정 육종가). `KPN 유전능력 자료.xlsx`에서 **아빠 KPN 번호로 그 행을 찾아(VLOOKUP) 육종가를 복사**. 예: 아빠 A의 근내지방도 육종가 2.5 → 송아지 `ebv_marbling=2.5`. **누수 0**(우리 등급 안 씀).

**③ 조상 본인등급 — `mother_own_grade`·`father_own_grade`** *(채택)* — "이 송아지의 **어미·아비가 받은 실제 등급**". 어미번호로 우리 데이터에서 그 어미 행을 찾아 `grade_num` 복사. 단 **어미가 송아지보다 먼저 판정된 경우만**(`어미 JUDGE_DATE < 송아지 JUDGE_DATE`, 안 그러면 미래 정보=누수). 예: 어미가 2년 전 1++B(14) → 송아지 `mother_own_grade=14`.

**④ 자손 평균등급 = 타깃 인코딩(Target Encoding, TE) — `kpn_prog_grade`** *(기각)* — "이 종모우의 **다른 자손들의 평균 등급**"(본인 뺌). 종모우별 `grade_num` 평균(자기 제외+스무딩). 예: A 자손 1000마리 평균 9.2 → A 새끼 값 9.2. **"Target Encoding"** = 종모우 번호를 "자손들의 타깃(등급) 평균"으로 변환한 것. **우리 타깃을 가공해 위험.**

**⑤ 또래 대비 체격 — `weight_vs_peer`** *(채택)* — "같은 **월령+성별** 또래 평균체중 대비 이 소가 얼마나 큰가" = 체중 ÷ 또래평균체중. 예: 30개월 거세 평균이 480kg인데 이 소가 528kg → 1.10. **타깃 안 씀(체중·월령·성별만) → 누수 0.** 트리가 raw로는 못 만드는 "그룹 상대값".

> **③⑤ vs ④ 한 줄 차이 (제일 중요)**: ③⑤는 **실제 측정값·다른 변수로만 만든 사실** → 안전. ④는 **자손들의 등급 평균을 우리가 만든 것(타깃 가공)** → 위험.

### 3.6.3 우리가 만든 파생변수 — 전체 목록과 검증 결과

격리 CV(2-fold, 누수안전)로 하나씩 검증한 결과를 모두 모았다. **노이즈 바닥은 ±0.0008**(2-fold·서브샘플) — 이보다 작은 Δ는 못 믿는다.

| 파생변수 | 무엇 | 누수 | CV Δ | 결정 |
|---|---|---|---|---|
| `KPN_NO_freq` | 종모우 빈도(자손 수) | 0 | (기존) | 유지 |
| `weight_vs_peer` | 월령+성별 또래 대비 체격 | 0(feature) | **+0.0021** | ✅ **채택** |
| `mother/father_own_grade` (+`has_*`) | 조상 본인 실제등급(날짜게이트) | 0(다른개체) | +0.0017 | ✅ 채택 |
| `ebv_marbling`·`cwt`·`rea`·`backfat`·`wt12`·`acc`, `has_ebv` | 외부 종모우 육종가 | 0(외부) | +0.0007 | 🔸 채택(주\*) |
| `kpn_prog_grade` (자손 TE) | 종모우 자손 평균등급 인코딩 | 높음(타깃가공) | **−0.0215** | ❌ **기각** |
| `daily_gain²` | daily_gain 제곱 | 0 | +0.0005 | ❌ 무의미(트리) |
| `daily_gain_z_by_sex` | 성별 내 일당증체 z | 0 | −0.0001 | ❌ 중립(중복) |
| `lineage_missing` / `ratio_고온_late` | 미등록플래그 / 출하전90일 더위 | 0 | +0.0006 / +0.0009 | ⚪ 노이즈밴드(보류) |
| ❌ `어미 자손평균(TE)` | 어미의 자손 평균등급 | **직접누수** | — | 🚫 **절대 금지**(어미≈자손 1:1) |

> **\* EBV 채택은 "규칙 예외"다.** EBV의 +0.0007은 **노이즈 바닥(0.0008)보다 작아** 격리 CV만 보면 `lineage_missing`·`late_heat`처럼 **"보류"가 맞다**. 그럼에도 채택한 이유는 ① 외부 공식 육종가라 **누수 0**이고 ② 등급의 결정요인(마블링)의 *유전 신호*라 **도메인 타당성**이 분명하기 때문 — 즉 **"탐지 한계 미만이나 도메인 근거로 채택"**한 의도적 예외다. 순수 데이터 규칙만 따른다면 빼도 무방하다(영향 ±0.0007).
>
> **그리고 진짜 메시지**: 채택 조합 이득(+0.0013)이 `weight_vs_peer` 단독(+0.0021)보다도 작다 = **신규 파생이 전부 탐지 한계 근처**라는 뜻. 0.20 천장의 근본 원인은 파생변수 부족이 아니라 **품질 형질(마블링·등지방)이 누수로 빠진 구조적 한계**다(아래 교훈 6, 결과종합 참고).

**핵심 교훈 6가지**

1. **자손 target-encoding = 기각(−0.02).** macro-F1·정확도가 함께 떨어짐(진짜 해로움). **농장 단위 split**에서 부는 농장당 1마리라 자손이 한 fold에 뭉쳐 → val에서 인코딩이 무력 → train/val 분포 어긋남. 타깃 가공 변수의 전형적 과적합.
2. **트리엔 제곱·구간화가 무의미.** `daily_gain²`는 양수의 단조변환 → split이 동일 → 정보 0(+0.0005는 노이즈). 제곱항·구간화는 **선형/로지스틱용 직관**이다.
3. **성별 내 정규화는 중복.** 성별로 정규화하면 성별↔등급이라는 강한 신호를 빼버린다(상관 0.52→0.30). 모델은 이미 raw daily_gain + 성별 더미를 갖고 있다.
4. **노이즈 바닥(±0.0008)을 의식.** `daily_gain²`(무의미)가 +0.0005 나온 게 그 증거. lineage_missing·late_heat도 같은 밴드라 "효과 있다"고 못 한다. 결합(+0.0013) < 단독(+0.0021)도 희석 사례.
5. **weight_vs_peer가 통한 이유.** "또래 대비 상대 체격"은 트리가 raw로 못 만드는 **그룹 상대값**이고, 육량(A/B/C, 도체중)을 **간접 프록시**한다.
6. **메타 교훈.** *외부값·feature유래*는 안전하고 *우리 타깃을 가공한 집계*는 위험하다. **farm-grouped split에선 조상-기반 인코딩의 검증 자체가 깨진다**(CV 설계가 결과를 좌우).

> **반영 상태**: 채택분(`weight_vs_peer`, `mother/father_own_grade`, `ebv_*`)은 `step11_features.csv`에 들어가 있고(track1 70개), test 빌드(셀 20-5b·5c)도 동일하게 만든다. 자손 TE·제곱·z는 **넣지 않음**. 원본 step11은 `step11_features_pre0612.csv`로 백업.

### 3.6.4 추가·검증 코드 (이어서 쓰는 틀)

> **이 셀은 "피처 선택"이지 "튜닝"이 아니다.** 고정된 파라미터(`PARAMS`)로 **"이 피처를 넣으면 점수가 오르나?"만** 본다. 하이퍼파라미터는 안 건드린다.
>
> **순서가 중요하다 (둘을 한 번에 하지 말 것):**
> 1. **이 셀(3.6.4)을 먼저** — 새 피처를 `add_candidates`에 넣고 격리 CV → **+0.0008 넘으면 채택, 아니면 기각** (고정 파라미터로 빠르게 판정)
> 2. 채택된 피처를 **step11에 추가 + 셀 20 test 빌드에도 추가** (3.6.5 체크리스트)
> 3. **그 다음에 셀 14(튜닝)를 다시 돌린다** — *확정된 피처셋*에 맞춰 하이퍼파라미터 최적화
> 4. 셀 15에서 5-fold로 최종 확정
>
> 왜 이 순서? **피처마다 튜닝을 다시 하면 비용이 폭발**한다. 그래서 "괜찮은 고정 파라미터로 피처를 먼저 고르고 → 최종 피처셋에서 딱 한 번 튜닝"이 정석이다. (피처 선택과 튜닝은 목적이 다른 별개 단계다.)

새 파생변수는 `add_candidates()`에 **한 블록 추가**하고 이 셀을 다시 돌리면 된다. (셀 6의 `dev`·`fold`, 셀 4의 `features_track1`, 셀 5의 `y` 사용)

```python
# ============================================================
# 파생변수 추가·검증 하니스 — 하나씩 격리 CV (오르면 채택/내리면 기각)
#   원칙: ① 누수 없게 (타깃 쓰면 OOF, 외부/feature유래면 그냥)  ② 하나씩 검증
# ============================================================
from sklearn.model_selection import train_test_split

def add_candidates(d):
    """후보 파생변수를 d(=dev)에 추가하고, {이름: [컬럼들]} 반환. 새 변수는 여기 추가."""
    cands = {}
    # ── 채택 예시: 또래 대비 체격 (타깃 미사용 → 누수 0) ──
    d["weight_vs_peer"] = d["WEIGHT"] / d.groupby(["AGE","JUDGE_SEX"])["WEIGHT"].transform("mean")
    cands["weight_vs_peer"] = ["weight_vs_peer"]
    # ── 기각 예시: 성별 내 z (중복) ──
    g = d.groupby("JUDGE_SEX")["daily_gain"]
    d["daily_gain_z_by_sex"] = (d["daily_gain"] - g.transform("mean")) / g.transform("std")
    cands["daily_gain_z_by_sex"] = ["daily_gain_z_by_sex"]
    # ── 무의미 예시: 제곱 (트리 no-op) ──
    d["daily_gain_sq"] = d["daily_gain"] ** 2
    cands["daily_gain_sq"] = ["daily_gain_sq"]
    # ↓↓↓ 새 파생변수는 여기에 추가 + cands에 등록 ↓↓↓
    # d["새변수"] = ...
    # cands["새변수"] = ["새변수"]
    return cands

cands = add_candidates(dev)
PARAMS = dict(objective="multiclass", num_class=n_classes, learning_rate=0.05, n_estimators=500,
              max_depth=8, num_leaves=101, min_child_samples=66, subsample=0.888, subsample_freq=1,
              colsample_bytree=0.813, class_weight="balanced", n_jobs=-1, verbosity=-1, random_state=SEED)

def iso_cv(extra, n_folds=2, sub=200_000):
    sc = []
    for k in range(n_folds):
        tr = dev[dev["fold"] != k]; va = dev[dev["fold"] == k]
        trs, _ = train_test_split(tr, train_size=min(sub, len(tr)),
                                  stratify=tr["y"], random_state=SEED)
        cols = features_track1 + extra
        m = lgb.LGBMClassifier(**PARAMS).fit(
                trs[cols], trs["y"], eval_set=[(va[cols], va["y"])],
                callbacks=[lgb.early_stopping(40, verbose=False), lgb.log_evaluation(0)])
        sc.append(f1_score(va["y"], np.asarray(m.predict(va[cols])).ravel(), average="macro"))
    return np.mean(sc)

base = iso_cv([])
print(f"C0 기준(현재 {len(features_track1)}피처) = {base:.4f}")
for name, cols in cands.items():
    s = iso_cv(cols)
    verdict = "✅ 채택" if s - base > 0.0008 else ("⚪ 노이즈/무효" if abs(s-base) <= 0.0008 else "❌ 기각")
    print(f"  +{name:24s} {s:.4f}  ({s-base:+.4f})  {verdict}")
```

> **타깃을 쓰는 변수(target-encoding류)를 추가할 땐** `add_candidates` 안에서 만들면 안 된다(전체 dev로 평균내면 누수). 대신 `iso_cv`의 fold 루프 안에서 **train(tr)으로만** 통계를 만들어 tr·va에 적용해야 한다(자기제외·날짜게이트). 3.6.2 ④의 누수 통제 참고.

### 3.6.5 다음 사람용 — 새 파생변수 추가 체크리스트

1. **아이디어**: SHAP·혼동행렬·EDA에서 "모델이 약한 지점"을 겨냥 (예: A/B/C 육량 → 체격 관련).
2. **누수 점검**: 이 값을 **송아지 도축 전에 알 수 있나?** 타깃(등급·육질)을 직접 쓰면 → OOF·자기제외 필수. 외부값·다른 feature로만 만들면 → 그냥 OK.
3. **트리 적합성**: 제곱·구간화·곱셈 상호작용은 **트리엔 거의 무의미**(스킵). 트리가 못 만드는 건 **그룹 상대값**(또래 평균 대비, z-score)·**외부 조인값**.
4. **검증**: 3.6.4 `add_candidates`에 추가 → 격리 CV → **+0.0008 넘으면** 채택.
5. **채택 시 3곳 반영**: ① step11에 컬럼 추가(또는 셀 3 직후 생성) ② 셀 20 test 빌드에 **동일 계산** 추가(train 기준) ③ 3.6.3 목록표에 한 줄.
6. **마지막**: 채택분 다 모아 전체 5-fold로 최종 숫자 확정.

## 3.7 클래스별 임계값(가중) 최적화 — macro-F1 직접 끌어올리기 (후처리)

스태킹보다 먼저 시도할 만한, 싸고 깨끗한 후처리다. 모델은 그대로 두고 **예측을 지표(macro-F1)에 맞게 재정렬**한다. **이득 크기는 미리 단정하지 않고 아래 3.7.4의 홀드아웃 실측으로 확인한다.**

### 3.7.1 왜 argmax가 macro-F1에 최적이 아닌가

지금은 `predict_proba` 후 **가장 높은 확률(argmax)**로 등급을 정한다. argmax는 *정확도*엔 자연스럽지만 **macro-F1엔 최적이 아니다**:

- macro-F1 = **16개 클래스 F1의 평균** → **희귀 등급 하나의 F1이 평균을 크게 좌우**한다.
- 희귀 등급(등외·3C 등)은 확률이 잘 안 올라와서 argmax로는 거의 안 뽑힘 → F1≈0 → macro 끌어내림.
- **해결**: 클래스마다 결정 가중치 `w_c`를 곱해 `argmax(proba × w)`. 희귀 등급의 `w`를 키우면 더 자주 뽑혀 그 등급 F1↑ → macro-F1↑. **`w`를 macro-F1이 최대가 되게 데이터로 찾는다.**

> **과한 기대는 금물 (중요)**: 우리 모델은 이미 `class_weight="balanced"`라 희귀 등급 확률을 한 번 끌어올려놨다. 그 위에 또 `w`를 곱하는 건 **일부 중복**이라, balanced가 이미 먹은 몫만큼 한계이득이 줄어든다. → 이득은 **반드시 홀드아웃 실측(3.7.4)으로 확인**하고, "얼마 오른다"고 미리 단정하지 않는다.

### 3.7.2 ⚠️ 누수 — `w`는 OOF에서 찾고, 보고하는 홀드아웃엔 "적용만"

`w`를 **홀드아웃에서 맞춘 뒤 그 홀드아웃 점수를 보고**하면 지표를 과적합한 가짜 점수다(메타 누수). 올바른 절차: **dev의 OOF 확률에서 `w`를 찾고 → 홀드아웃·test엔 그 `w`를 적용만** 한다.

### 3.7.3 셀 22 (코드) — OOF 확률 생성 + 가중치 좌표상승 최적화

```python
# (1) 튜닝 모델의 OOF 확률 — 각 행 확률은 그 행 fold를 안 본 모델에서 (누수 0)
K = n_classes
proba_oof = np.zeros((len(X_t1), K))
for tr, va in fold_indices:
    Xtr, Xva = prepare_X(X_t1.iloc[tr], X_t1.iloc[va])
    m = lgb.LGBMClassifier(**best_params).fit(Xtr, y_dev.iloc[tr])
    proba_oof[np.ix_(va, m.classes_.astype(int))] = m.predict_proba(Xva)

# (2) 클래스 가중치 w 를 macro-F1 최대가 되게 — 좌표상승(coordinate ascent)
def mf1(proba, y, w):
    return f1_score(y, (proba * w).argmax(1), average="macro")

y_arr = y_dev.to_numpy()
base = mf1(proba_oof, y_arr, np.ones(K))
w = np.ones(K)
for _ in range(4):                                   # 몇 라운드 반복
    for c in range(K):
        cur = w.copy(); best_wc, best_f = w[c], mf1(proba_oof, y_arr, w)
        for cand in np.linspace(0.2, 4.0, 39):       # 그 클래스 가중치만 훑기
            cur[c] = cand; f = mf1(proba_oof, y_arr, cur)
            if f > best_f: best_wc, best_f = cand, f
        w[c] = best_wc
tuned = mf1(proba_oof, y_arr, w)
print(f"가중 튜닝: argmax {base:.4f} → 가중 {tuned:.4f}  (+{tuned-base:.4f})")
np.save("../../data/processed/4_model/19_class_weights.npy", w)   # 홀드아웃·test에 재사용
```

### 3.7.4 셀 22b (코드) — 홀드아웃으로 '진짜' 이득 측정 (★ 필수)

3.7.3이 출력하는 `+{tuned-base}`는 **`w`를 맞춘 그 OOF에서 다시 잰 in-sample 값**이라 수학적으로 항상 양수다(상한일 뿐, 달성치가 아님). **진짜 이득은 `w`를 처음 보는 홀드아웃에 적용**해 재야 한다 — 셀 18의 `holdout_model`·`X_hold`·`y_hold`를 재사용한다.

```python
ph = holdout_model.predict_proba(X_hold)             # 셀 18에서 만든 dev-학습 모델
b  = f1_score(y_hold, ph.argmax(1), average="macro")           # argmax 기준
wf = f1_score(y_hold, (ph * w).argmax(1), average="macro")     # ★ dev OOF에서 찾은 w 적용
print(f"홀드아웃 가중 효과: {b:.4f} → {wf:.4f}  ({wf-b:+.4f})")   # 이 Δ가 진짜 이득
```

- 이 **홀드아웃 Δ**가 채택 기준이다: **양수면 채택**(3.9에서 제출에 반영), 0 근처/음수면 보류. 보고서엔 *이 실측치*를 적는다(미확인 단정 금지).
- **정확도는 약간 내려갈 수 있다**(희귀 등급을 더 뽑아 다수 등급 일부 희생) — 지표가 macro-F1이라 OK.
- **0.20 천장 자체는 못 깬다**(구조적). 있는 신호를 지표에 맞게 정렬하는 싼 마무리다.

## 3.8 스태킹 앙상블 — 여러 모델을 메타모델로 합치기 (★ 누수 주의)

### 3.8.1 스태킹이란 — 쉽게 풀어서

**한 줄 비유 (협진)**: 어려운 환자를 **여러 전문의에게 따로 진단받고**, 그 소견들을 종합하는 **수석의(메타)**가 최종 판정을 내리는 병원 협진과 같다. 모델 하나에 운명을 걸지 않고, 여러 모델의 "의견"을 똑똑하게 합치는 것이다.

**왜 합치면 나을까?** 모델마다 잘 맞히는 구간이 다르다 — LightGBM은 어떤 등급에 강하고 CatBoost는 다른 등급에 강할 수 있다. 한 모델만 쓰면 그 모델의 약점을 그대로 떠안지만, **여러 모델을 합치면 서로 다른 실수를 상쇄**해 평균적으로 더 정확해진다. (반 친구 여럿이 시험문제를 따로 풀고 다수결로 답을 정하면, 혼자 풀 때보다 보통 더 맞는 것과 같다.)

**2단 구조 (Level-0 → Level-1)**

| 단계 | 누가 | 무엇을 하나 |
|---|---|---|
| **Level-0 (베이스)** | LightGBM·XGBoost·CatBoost·로지스틱 **4종** | 각자 따로 학습 → 소 한 마리에 대해 **16개 등급 확률**을 낸다 (모델당 숫자 16개) |
| **Level-1 (메타)** | 작은 로지스틱 **1개** | 베이스 4종의 확률(4×16 = **64개 숫자**)을 입력받아 **최종 등급**을 정한다 |

**구체적 예시** — 소 한 마리:
- LightGBM: "1++B일 확률 0.40, 1++A 0.30, …"
- CatBoost: "1++A일 확률 0.45, 1++B 0.25, …"
- XGBoost·로지스틱: 또 다른 확률들
→ 메타는 이 **64개 숫자 패턴**을 보고 *"이런 패턴이면 보통 1++A더라"*를 **과거 데이터로 배워서** 최종 등급을 찍는다. 즉 메타가 "어떤 모델 말을 언제 더 믿을지"를 학습한다.

**단순 보팅(평균)과 뭐가 다른가?** 보팅은 4모델 확률을 그냥 **1/4씩 똑같이** 평균낸다(누가 잘하든 동등). 스태킹은 **"어느 모델이 어느 등급에서 믿을 만한지"의 가중치를 메타가 데이터로 학습**한다 → 더 똑똑한 합치기다.

> **메타는 왜 또 (단순한) 로지스틱?** 베이스들이 이미 복잡한 패턴을 다 뽑아놨으니, 메타는 그걸 **단순 조합만** 하면 된다. 메타까지 복잡한 모델을 쓰면 64개 입력에 **과적합**한다 → 단순한 로지스틱이 정석이다.

### 3.8.2 ⚠️ 누수 함정 — `sklearn StackingClassifier`를 기본값으로 쓰지 마라

메타는 반드시 **OOF(out-of-fold) 예측**으로 학습해야 한다. 베이스가 *본* 데이터의 예측으로 메타를 학습하면, 베이스가 외운 정답을 메타가 그대로 베껴 **누수**가 된다.

> **결정적**: `sklearn.ensemble.StackingClassifier`는 OOF를 자체 `cv`(기본 **무작위 KFold**)로 만든다. 이건 우리 **농장 단위 split을 무시** → 같은 농장 소가 베이스 train과 메타 val에 흩어져 **농장 누수**가 난다(2-5절에서 막은 바로 그 누수). → **기본 cv로 쓰면 안 된다.** 우리는 분류·회귀가 공유하는 **`fold_indices`로 직접 OOF**를 만든다.

### 3.8.3 셀 23 (코드) — 누수안전 수동 스태킹

```python
from sklearn.linear_model import LogisticRegression

def make_bases():                       # Level-0 (predict_proba 되는 4종)
    return {
        "lgb":   lgb.LGBMClassifier(**best_params),
        "xgb":   XGBClassifier(objective="multi:softprob", num_class=n_classes,
                               learning_rate=0.05, n_estimators=500, max_depth=8,
                               subsample=0.8, colsample_bytree=0.8, n_jobs=-1,
                               eval_metric="mlogloss"),  # ★ softmax 아닌 softprob
        "cat":   CatBoostClassifier(iterations=500, depth=8, learning_rate=0.05,
                                    auto_class_weights="Balanced", verbose=0),
        "logit": LogisticRegression(max_iter=2000, class_weight="balanced", n_jobs=-1),
    }

n, K = len(X_t1), n_classes
oof = {name: np.zeros((n, K)) for name in make_bases()}

# ★ 우리 fold_indices로 OOF 확률 생성 (sklearn 자동 cv 금지 — 농장 누수)
for fi, (tr, va) in enumerate(fold_indices):
    Xtr_f, Xva_f = prepare_X(X_t1.iloc[tr], X_t1.iloc[va])   # ★ 중앙값은 train fold에서만 (누수 0)
    ytr = y_dev.iloc[tr]
    sw  = compute_sample_weight("balanced", ytr)            # XGB용 균형 가중
    sc  = StandardScaler().fit(Xtr_f)                        # 로지스틱용 스케일
    for name, mdl in make_bases().items():
        Xtr = sc.transform(Xtr_f) if name == "logit" else Xtr_f
        Xva = sc.transform(Xva_f) if name == "logit" else Xva_f
        if name == "xgb":
            mdl.fit(Xtr, ytr, sample_weight=sw)             # ★ XGB만 balanced 누락 → 보충
        else:
            mdl.fit(Xtr, ytr)                               # lgb·cat·logit은 자체 balanced
        p = np.asarray(mdl.predict_proba(Xva))
        oof[name][np.ix_(va, mdl.classes_.astype(int))] = p  # 빠진 클래스 대비 정렬
    print(f"fold {fi} OOF 완료")

# Level-1 메타: OOF 확률을 가로 결합(n×64) → 다항 로지스틱, 같은 fold로 OOF 평가
meta_X = np.hstack([oof[name] for name in oof])
meta_oof = np.zeros(n, dtype=int)
for tr, va in fold_indices:
    meta = LogisticRegression(max_iter=3000, class_weight="balanced")
    meta.fit(meta_X[tr], y_dev.iloc[tr]); meta_oof[va] = meta.predict(meta_X[va])

print(f"스태킹 Macro-F1 = {f1_score(y_dev, meta_oof, average='macro'):.4f}  "
      f"(단일 튜닝 LGBM {tuned_df['macro_f1'].mean():.4f} 대비)")
```

> **제출용**: 베이스 4종을 **전체 dev로 재학습** → test 확률 예측 → 가로 결합 → (위 OOF로 학습한) 메타에 통과시켜 최종 등급. 셀 20·21에 베이스별 `predict_proba`를 추가하면 된다.
>
> **작은 주의(이중 OOF의 미세 낙관)**: 메타를 OOF 확률 위에서 다시 CV 평가하면 추정이 *아주 약간* 낙관적이다(엄밀히는 중첩 CV 필요). 실무에선 이 정도는 허용하고, **최종 판단은 홀드아웃**(셀 18 방식)으로 한 번 더 확인한다.

### 3.8.4 기대치 — 솔직하게

| 항목 | 현실 |
|---|---|
| 기대 이득 | **작다 (+0.005~0.01 수준).** 베이스 4종이 **같은 58~70 피처·같은 0.20 천장**을 봐서 예측이 서로 닮았다(상관↑) → 합쳐도 새 정보가 적다 |
| 스태킹이 크게 먹히는 조건 | 베이스가 **서로 다를 때**(다른 피처·다른 알고리즘 계열). 여기선 다양성이 제한적 |
| 비용 | 4모델 × 5fold = 20번 학습(XGB·CatBoost 느림) → 마감 직전 **마지막 한 끗**용 |

> **핵심**: 스태킹은 0.20 천장을 **못 깬다.** 천장의 원인은 모델이 아니라 **품질 형질(마블링·등지방)이 누수로 빠진 구조적 한계**(3.6·4장). 스태킹은 "있는 신호를 마지막까지 짜내는" 마무리 기술이지, 돌파구가 아니다. **먼저 단일 튜닝 LGBM으로 제출이 도는 걸 확인한 뒤** 여유가 있을 때 시도하라.

## 4. 결과 해석 가이드 — 숫자를 받아들고 무엇을 볼 것인가

> 결과 숫자는 여러분이 직접 돌려서 얻는다. 아래는 "읽는 순서"다.

**① CV 평균 ± 표준편차부터.** 평균이 성능, 표준편차가 안정성이다. fold 간 편차가 크면(예: ±0.02 이상) 모델이 데이터 구획에 민감하다는 뜻 — 파라미터보다 피처/분할을 먼저 의심한다.

**② Macro-F1과 정확도의 격차.** 정확도는 높은데 Macro-F1이 낮으면 다수 등급만 잘 맞추고 소수 등급을 버리고 있다는 신호다. classification_report에서 어느 등급의 recall이 바닥인지 확인하라.

**③ 혼동행렬은 대각선 주변을 본다.** 한우 등급은 순서가 있어서 **인접 등급 혼동(1++B↔1++A)은 가벼운 오류, 건너뛰기 혼동(1++A↔2C)은 심각한 오류**다. 행 기준 % 행렬에서 오류가 대각선 부근에 몰려 있으면 모델이 "품질의 순서"는 학습한 것이다. 특히 같은 숫자 등급 내 A/B/C 혼동(예: 1+A vs 1+B — 육량 차이)이 많은지, 숫자 등급 간 혼동(1+ vs 1 — 근내지방 차이)이 많은지를 구분해 보라. 전자가 많다면 육량 관련 피처(WEIGHT, daily_gain)가, 후자가 많다면 품질 관련 신호가 부족한 것이다.

**④ 트랙1 vs 참고-사후의 격차가 보고서의 핵심 문장.** 사후(육질 포함)가 크게 높게 나오는 것이 정상이다 — 등급은 육질 측정값으로 매겨지기 때문. 그 격차 자체가 "사전 정보만으로 예측의 한계는 어디까지인가"라는 분석 결과다.

**⑤ SHAP 중요도는 EDA와 맞춰본다.** 13~17회차에서 daily_gain(r=+0.522), WEIGHT(+0.475), 성별이 강했다. SHAP 상위권이 이와 일치하면 모델이 합리적으로 배우고 있는 것이고, 전혀 뜬금없는 변수가 1위면 누수나 버그를 의심하라. summary plot에서는 점 색(변수값 높낮이)과 좌우 위치(SHAP 부호)를 함께 읽는다 — "daily_gain이 높을수록(빨강) 1++A 확률을 올린다(오른쪽)" 같은 문장으로.

**⑥ CV vs 홀드아웃 격차 = 일반화 점검.** 거의 같으면 분할·모델링이 건강한 것. 홀드아웃이 눈에 띄게 낮으면 (농장 분할 덕에 가능성은 낮지만) CV에 과적합한 것이다.

**⑦ 등외 등급의 F1은 따로 언급하라.** 5,540마리(0.23%)뿐이고 노폐우 등 이질 집단이라 F1이 낮게 나올 수 있다. 보고서에 "등외 제외 시 Macro-F1" 도 병기하면 분석의 정직성이 드러난다.

## 5. 성능 향상 가이드 — 일주일 동안 시도할 것들 (우선순위순)

### 5-1. 파라미터 손대기 (효과 큰 순)

| 우선순위 | 무엇을 | 어떻게 | 기대 효과 |
| --- | --- | --- | --- |
| 1 | `learning_rate` ↓ + `n_estimators` ↑ | 0.02~0.03 + 2000~3000 (early stopping 믿고) | 거의 항상 소폭 상승. 시간↑ |
| 2 | `num_leaves` / `max_depth` | Optuna 범위를 num_leaves 31~511로 확장 | 데이터가 커서 복잡도 여유 있음 |
| 3 | `min_child_samples` | 20~300 탐색 | 소수 등급 과적합/과소적합 균형 |
| 4 | `N_TRIALS` ↑ | 50~100회 (밤새 돌리기) | 탐색 공간 충분히 커버 |
| 5 | Optuna 평가를 다중 fold로 | objective에서 fold 0,1 평균 사용 | 튜닝 결과의 신뢰성 ↑ (시간 2배) |

### 5-2. 클래스 가중 커스텀 (Macro-F1 직공)

"balanced"는 출발점일 뿐이다. Macro-F1은 모든 클래스를 동등하게 보므로, **소수 클래스 가중을 balanced보다 더 키우거나 줄이며** 최적점을 찾아라:

```python
# 예: balanced 가중에 지수 γ를 적용 (γ=1이 balanced, γ>1이면 소수 클래스 더 강조)
counts = y_dev.value_counts().sort_index().values
w = (len(y_dev) / (n_classes * counts)) ** GAMMA      # GAMMA를 0.5~1.5 탐색
class_weight = {i: w[i] for i in range(n_classes)}
# LGBMClassifier(class_weight=class_weight, ...)
```

### 5-3. 피처 추가 — 시군구 OOF Target Encoding (18회차에 미뤘던 것)

sigungu(184종)는 정보가 많지만 그대로 못 쓴다. **fold 안에서만** 평균 타깃으로 인코딩하면 누수 없이 쓸 수 있다:

```python
def add_te(dev, col="sigungu", target="grade_num"):
    te = np.full(len(dev), np.nan)
    for k in range(5):
        tr_mask = dev["fold"] != k
        mapping = dev[tr_mask].groupby(col)[target].mean()      # fold 밖 데이터만으로
        te[~tr_mask.values] = dev.loc[~tr_mask, col].map(mapping).values
    dev[f"{col}_te"] = te
    return dev
# 홀드아웃/test에는 dev 전체로 만든 mapping을 적용
```

같은 방식으로 `stn`(관측소), `eupmyeondong`도 시도 가치가 있다. **주의**: mapping은 반드시 해당 fold의 train에서만 — 전체로 만들면 그게 바로 Target Encoding 누수다.

### 5-4. 모델 구조 아이디어

- **앙상블(soft voting)**: LGB·XGB·CatBoost의 `predict_proba` 평균 후 argmax. 모델들이 서로 다른 실수를 하면 1~3%p 오르는 경우가 흔하다.
- **2단계 분해**: 등급 = 숫자등급(1++/1+/1/2/3/등외, 6클래스) × 육량(A/B/C, 3클래스). 두 모델로 나눠 예측 후 조합 — 클래스당 표본이 늘어 소수 등급에 유리할 수 있다.
- **순서형(ordinal) 활용**: 등급에 순서가 있으므로 grade_num 회귀 후 반올림→클래스 변환도 비교해 볼 것 (Macro-F1로 동일 평가).
- **등외 별도 처리**: 등외(노폐우 다수)만 먼저 이진 분류로 걸러내고 나머지 15등급을 분류하는 2단계.

1. **문제**: 16등급, 58배 불균형 → 평가지표는 Macro-F1, 모든 모델에 클래스 가중 필수.
